# Bitvoya MCP v0.3.2

Correctness and token-budget release for the hosted Bitvoya MCP endpoint.

Hosted endpoint:

- `https://bitvoya.com/api/mcp`

## Fixes

- `search_hotels` works again. Since v0.3.0 every call failed with `resolvedOffset is not defined`.
- `get_hotel_rooms`, `prepare_booking_quote`, `create_booking_intent`, `create_booking` and `get_booking_state` now advertise their real input schemas in `tools/list`. They used to advertise an empty object, so agents could not see `hotel_id`, `checkin`, `checkout` or any other parameter. camelCase names (`hotelId`, `adultNum`) and numbers sent as strings are still accepted.
- The "today" date that tools use for relative dates is read when each MCP session starts. It used to be fixed when the server process started, so a long-running gateway told agents a date that was days old.
- Free-form requests that match nothing as a whole now find the destination inside them, for example `巴黎 蜜月 安静 有特权的酒店` or `巴黎蜜月酒店`. Only an exact city name counts, and the result says which word was used.

## Smaller results

Discovery tools accept `detail`:

- `brief` (default): every distinct fact is kept once. Sentences restated across `static_story`, `grounding_excerpt`, `decision_brief` and `bitvoya_value_brief` are dropped, the active shortlist is no longer serialised twice, city context is not copied into every hotel, benefit descriptions appear the first time their id shows up, and prose fields are capped at 280 characters.
- `full`: the complete payload, as in v0.3.1.

Measured on production data (Paris, 5 hotels, 3 nights):

| Tool | v0.3.1 text | v0.3.2 brief |
| --- | --- | --- |
| `start_hotel_search` | 249 KB (~62k tokens) | 39 KB (~10k tokens) |
| `get_hotel_detail` | 98 KB (~24k tokens) | 15 KB (~4k tokens) |
| `get_hotel_rooms` | 156 KB (~39k tokens) | 42 KB (~10k tokens) |

Booking tools (`create_booking`, `prepare_booking_quote`, `create_booking_intent`, `get_booking_state` and the internal executor tools) are never shaped.

## Protocol

- The server now sends `instructions` at initialize: today's date, the usual tool flow, and how prices and handoff work.
- The text block of each result carries compact JSON instead of indented JSON.
- `tools/list` shrank from 68 KB to 49 KB. The date sentence is no longer repeated in every date parameter, and the shared output schema describes only the stable envelope fields.
